Multi-store architecture concept

One support platform. Separate store sessions.

Multiple ecommerce businesses can use the same service at the same time. Each signed-in store gets its own session, and requests should only return records belonging to that store.

3 separate sessions
Important: This is a visual architecture example with fictional data, not a login or security feature. The current demo API has no authentication or tenant-level data isolation. Do not use real customer data or treat this demo as production-ready.

How isolation should work

  1. 1

    Sign in
    Verify the store user and create a secure session.

  2. 2

    Resolve the store identity
    Get the tenant ID from the trusted session—not from a browser-supplied store ID.

  3. 3

    Scope every request
    Filter reads and writes by that tenant ID; deny access when the record belongs to another store.

Example server-side filter:
findOne({ tenantId: session.tenantId, orderId })
